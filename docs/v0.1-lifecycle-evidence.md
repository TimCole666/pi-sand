## Current v0.1 guarantees

- A normal Linux launch establishes or connects to the loopback Local Agent Service and opens the supported Desktop without terminal/port management.
- Agents, canonical workspace associations, Turns, transcript messages, and committed attachment metadata are durable in service-owned SQLite.
- Desktop selection and unsent per-Agent drafts, including live staged attachment references, are persisted as presentation state.
- Pi runs with its normal installed tools, extensions, and skills; pi-sand owns no second planner or context manager.
- Active work, streaming, Stop, failure, reconnect, independent workspace concurrency, and service-restart safety remain scoped to the affected Agent and Turn. Process groups are best-effort cleanup rather than complete containment; unrestricted Pi tools may create descendants outside the recorded PGID.
- After a service lifetime boundary in the same Linux boot, an unresolved real Pi worker keeps its workspace unavailable. This remains true after a graceful service shutdown even if best-effort PGID cleanup sees the recorded group disappear. A Linux reboot supplies the v0.1 complete process-lifetime proof via boot ID; pi-sand does not adopt, replay, or resume the old worker.
- The supported Desktop, service integration, and small Real-Pi smoke layers remain distinct. The Real-Pi layer contains basic execution, Pi-native two-Turn continuity, and attachment-consumption proofs.

## Explicitly deferred

v0.1 does not permit concurrent mutation of one canonical workspace, worker adoption, automatic replay/resume, a scheduler/queue/worker pool, a generic provider/runtime abstraction, stronger cgroup-style process containment, remote clients, custom model memory, exhaustive activity UI, exact unread/waiting semantics, voice, reply-context behavior, or pixel-perfect Grok fidelity.
