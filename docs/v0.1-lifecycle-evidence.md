# v0.1 lifecycle evidence and compatibility boundary

This record applies the evidence labels in `SPEC.md` to the lifecycle behavior implemented by the v0.1 unattended-Agent journey. It records user-visible expectations; it does not prescribe Grok Bot's process topology or source-level design.

| Behavior | Classification | Evidence and v0.1 implementation |
| --- | --- | --- |
| A submitted request has a visible active state and streamed assistant text before a terminal result. | **Evidence-backed** | `SPEC.md` core stories 11–13 and the Pi JSON/RPC contract recorded in `docs/pi-integration-spike.md`. The deterministic Desktop acceptance test exercises the same semantic HTTP/SSE seam. |
| Closing and reopening the Desktop does not cancel an active Turn and returns the same Agent/transcript. | **Evidence-backed** | This is the product-defining compatibility behavior in `SPEC.md` core stories 15–17. `test/desktop-e2e.test.js` records the close → active snapshot → reopen → complete journey. |
| A reconnect does not duplicate or reorder visible transcript entries. | **Evidence-backed** | `SPEC.md` core story 17. The Desktop replaces its view with authoritative service snapshots; messages have durable IDs and SQLite sequence ordering. |
| Interrupt reaches a stable terminal state while preserving persisted content. | **Evidence-backed** | `SPEC.md` core stories 18–19 and the observed Pi RPC `abort` behavior in the integration spike. Deterministic service coverage verifies the completion/interrupt race. |
| An unexpected Pi child exit becomes one failed Turn, while history remains usable. | **Evidence-backed** | `SPEC.md` core story 20 and the observed SIGKILL close behavior in the integration spike. The service acceptance tests cover a streaming failure and a later submission. |
| On Local Agent Service restart, completed history restores and an unfinished Turn becomes `interrupted` without replay. | **Extension** | This is pi-sand's documented v0.1 safety rule, chosen because safe Pi crash continuation is unknown. It is not an assertion about Grok internals. |
| The concrete Pi JSONL/RPC start, stream, abort, and close event shapes. | **Observed** | Recorded against Pi 0.84.2 on Linux in `docs/pi-integration-spike.md`; the optional real-Pi smoke retests a concrete workspace mutation through the production adapter. |
| A killed Pi session can safely continue, and the exact UI fidelity of unresearched Grok surfaces. | **Unknown** | v0.1 does not adopt workers, replay requests, or claim session recovery. Visual/pixel-level compatibility requires feature-specific reference research. |
| A local Agent Service owns the Pi process independently of the Desktop, and the application owns durable Agent/Turn/message identity. | **Inferred** | This is the smallest architecture that satisfies the evidence-backed lifetime behavior. It is intentionally not a reconstruction of a Grok Coordinator/Host/Supervisor topology. |

## What v0.1 guarantees

- one durable Agent can retain its workspace association, transcript, and terminal Turn history in local SQLite;
- ordinary natural-language requests create a durable user message before Pi work starts;
- the Local Agent Service owns the active Pi child, streams selected assistant text to the Desktop, and emits a simple active/idle state;
- Desktop reconnect receives an authoritative snapshot and later semantic updates, without client-side database access;
- interrupt, abnormal Pi exit, and service-restart reconciliation produce one explicit terminal product state while preserving existing transcript entries; and
- a later request can be submitted after failure, interruption, or restart reconciliation.

## Deferred explicitly

v0.1 does not promise concurrent Agents/workspaces, recovery or adoption of an in-flight Pi process, replay/retry of a request, remote clients, a generic runtime/provider abstraction, custom context or memory management, a workflow/planning loop around Pi, exhaustive tool activity UI, or pixel-perfect Grok Bot fidelity.
